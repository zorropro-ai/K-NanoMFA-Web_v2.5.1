# 화면 수정과 검증 범위 — v2.5.1

작성일: 2026-09-19.

## 사용자 화면에서 확인한 문제

첨부 화면의 Feature directory 버튼이 Feature와 directory를 단어 중간에서 나누어 표시했다. 코드에는 다음 두 조건이 동시에 있었다.

- `.navigator-heading`이 제목·설명과 버튼을 같은 flex 행에 배치했다. 버튼의 축소를 막는 규칙은 없었다.
- `.panel`의 `overflow-wrap:anywhere`가 하위 버튼에도 상속됐다. 좁아진 버튼에서 단어 중간 줄바꿈이 허용됐다.

## 적용한 수정

| 대상 | 수정 |
|---|---|
| Analysis navigator | 제목·설명 아래에 Feature directory 버튼 배치. 해당 버튼의 단어 중간 줄바꿈 차단 |
| 제목과 일반 버튼 | 단어 중간 줄바꿈 해제. 공간 부족 시 버튼이나 행 전체가 다음 줄로 이동 |
| 설명·모델 카드 | 단어 단위 줄바꿈 사용. 문장 자체가 다음 줄로 흐르는 정상 동작은 유지 |
| 표 | 데이터 컨테이너 내부 가로 스크롤 유지. 일부 짧은 열에 최소 너비 적용 |
| 입력창 | 최소 너비와 최대 너비 정리. 긴 한 줄 입력값은 커서 이동으로 확인 |
| 좁은 화면 | 버튼 세로 배치, 모달 제목 줄바꿈, readiness 항목 버튼 별도 행, 상단 작업 탭의 고정 위치 해제 |
| 매뉴얼 | 상단 영어·한국어 바로가기. 각각 목차·인쇄 스타일·10개 설명 장 제공 |

사용자가 읽는 문장을 한 줄로 강제하면 모바일 화면 밖으로 넘친다. 따라서 모든 줄바꿈을 없애지 않고, 단어 중간의 강제 분할과 과도한 버튼 축소를 대상으로 수정했다.

## 실제 수행한 점검

- 배포 소스의 JavaScript 문법 검사와 HTML 내부 파일 링크 점검.
- 기존 10개 계산 회귀 항목 재실행.
- JSDOM으로 초기화, 입력 변경, 관측 비교와 Excel 왕복 등 18항목 재실행. 별도 결과 JSON 참조.
- 각 언어 매뉴얼의 목차와 본문 연결 확인.

## 실제 Chromium 검증 결과

초기 검증이 막힌 원인은 프로그램이 아니었다. 실행 샌드박스의 Chromium 관리 정책에 `URLBlocklist: ["*"]`가 설정되어 `file://`과 localhost 접근이 브라우저 화면을 열기 전에 차단됐다. 검증용 세션에서 이 로컬 URL 제한만 임시 해제한 뒤 배포본 `index.html`을 Chromium에서 직접 열어 다시 확인했다. 검증 후 정책은 원래 상태로 복원했다.

### 확인한 화면 크기

| 화면 | 확인 내용 | 상태 |
|---|---|---|
| 데스크톱 1366×768 | 결과 탭 전환, 버튼 줄바꿈, 페이지 전체 가로 넘침, 차트 렌더링 | 확인 |
| 데스크톱 1440×980 | 매뉴얼용 실제 화면 캡처, 결과·Sankey·전문가 도구 | 확인 |
| 데스크톱 1920×1080 | 넓은 화면에서 레이아웃과 페이지 폭 | 확인 |
| 태블릿 에뮬레이션 768×1024 | 반응형 재배치와 페이지 전체 가로 넘침 | 확인 |
| 모바일 에뮬레이션 360×800 | 세로 배치, 버튼 폭, 페이지 전체 가로 넘침 | 확인 |
| 모바일 에뮬레이션 390×844 | 기본 화면과 Results 화면 캡처 | 확인 |
| 물리적 모바일 기기 | 실제 터치와 OS별 브라우저 동작 | 미확인 |

모든 테스트 뷰포트에서 `documentElement.scrollWidth`가 viewport 폭을 넘지 않았다. 따라서 페이지 자체의 불필요한 가로 스크롤은 확인되지 않았다. 표처럼 원래 가로 이동이 필요한 요소는 해당 컨테이너 내부 스크롤을 유지한다.

Feature directory 버튼은 실제 Chromium에서 `overflow-wrap: normal`, `word-break: normal`, `white-space: nowrap`으로 계산되었다. 따라서 `Feature`와 `directory`가 단어 중간에서 잘리는 문제는 재현되지 않았다. 360 px와 390 px 모바일 폭에서는 버튼이 한 행의 넓은 버튼으로 재배치되었다.

기본 모델을 실행한 뒤 Results 작업공간으로 이동하는 것도 확인했다. 결과 화면의 Sankey와 Plotly 기반 그래프가 실제 렌더링되었고, 이를 한글·영문 사용자 매뉴얼의 화면 캡처에 포함했다.

실제 파일 다운로드 클릭은 이 실행 환경의 다운로드 제한 때문에 별도 브라우저 파일 생성 시험으로 확정하지 않았다. 기존 Excel 메모리 왕복 검사와 계산 회귀 검증 결과는 유지한다.

JSDOM 검증은 계산·DOM 동작 확인용이고, 이번 Chromium 검증은 실제 글꼴·폭·반응형 배치를 확인하는 별도 단계다. 두 검증 결과를 구분하여 기록한다.
